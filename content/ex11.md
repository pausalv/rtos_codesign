## Contexto y objetivo

En sistemas en tiempo real, el uso de `malloc` y `free` para gestión dinámica de memoria está desaconsejado: estas funciones tienen tiempos de ejecución no deterministas y pueden producir fragmentación del heap con el paso del tiempo. µC/OS-II ofrece una alternativa determinista: las **particiones de memoria** (*memory partitions*).

Una partición divide un bloque de memoria estática en un número fijo de bloques de tamaño uniforme. Las operaciones de obtención (*get*) y devolución (*put*) de bloques tienen tiempo de ejecución constante, lo que garantiza el determinismo temporal exigido en sistemas de tiempo real.

En este ejercicio usaremos una partición de memoria para cargar imágenes BMP desde el sistema de ficheros en memoria *on-chip* y mostrarlas en la pantalla VGA.

## Configuración de la partición de memoria

Cada imagen ocupa 320×240 píxeles con 2 bytes por píxel (formato RGB565), lo que da un tamaño de bloque de **320 × 240 × 2 bytes**. Al tener 2 imágenes, la partición tendrá 2 bloques.

En `init.h` defina los parámetros de la partición, completando el tamaño de bloque que falta:

```c
/* memory management */
#define NUM_MEMORY_BLOCKS 2
#define NUM_BYTES_PACKET  /* TODO: calcule el tamaño necesario en bytes para una imagen de 320x240 píxeles RGB565 */

OS_MEM *ImageMemory;
INT16U PixelMem[NUM_MEMORY_BLOCKS][NUM_BYTES_PACKET];

OS_MEM_DATA mem_data;

OS_EVENT *SemaphoreMemory;  /* semáforo contador: controla cuántos bloques quedan libres */
OS_EVENT *MutexMemory;      /* mutex: protege el acceso exclusivo a la memoria */
```

También en `init.h` añada el tipo `bool` necesario para la función de lectura BMP:

```c
typedef enum e_bool { false = 0, true = 1 } bool;
```

En `UCOS_Utilities()` de `init.c`, cree los elementos de sincronización y la partición:

```c
MutexMemory = OSMutexCreate(0, &error);
SemaphoreMemory = OSSemCreate(NUM_MEMORY_BLOCKS);

ImageMemory = OSMemCreate(PixelMem, NUM_MEMORY_BLOCKS, NUM_BYTES_PACKET * sizeof(INT8U), &error);
alt_ucosii_check_return_code(error);
```

## Función de lectura de imagen BMP

La función `Read_BMP_ZipFile(char *file_name)` lee un fichero BMP del sistema de ficheros y devuelve un puntero al bloque de memoria donde ha almacenado los píxeles decodificados. Internamente:

1. Abre el fichero con `fopen`.
2. Lee la cabecera BMP para obtener ancho, alto y bits por píxel.
3. Lee los píxeles en orden inverso (el formato BMP almacena las filas de abajo a arriba).
4. Convierte el formato RGB a RGB565 (2 bytes por píxel).
5. Almacena el resultado en un bloque de la partición de memoria.

## Tareas de control de imágenes

Estudie los ficheros descargados e implemente dos nuevas tareas:

**`TaskPicture`**: lee las imágenes del sistema de ficheros y las decodifica en los bloques de la partición. Para cada imagen:
1. Tome el mutex de memoria antes de acceder a la partición.
2. Solicite el semáforo contador (que indica si hay bloques disponibles).
3. Obtenga un bloque de la partición con `OSMemGet`.
4. Llame a `Read_BMP_ZipFile` para decodificar la imagen en ese bloque.
5. Libere el mutex.

**`ShowPicture`**: traslada periódicamente un bloque de la partición al buffer de la DMA de la VGA para visualizarlo en pantalla. Para ello copia los píxeles del bloque de memoria al `pixel_buffer` de la VGA.

Cree los ficheros `.c` y `.h` correspondientes, defina pilas y prioridades, y regístrelas en `main()`. Si el sistema supera el número máximo de tareas configurado en el BSP, incremente `OS_MAX_TASKS` y `OS_LOWEST_PRIO` desde el BSP editor.

### Cuestiones

Estudie el código de `TaskPicture` y responda:

1. ¿Por qué se necesitan dos elementos de sincronización (mutex + semáforo) para controlar la memoria?
2. ¿Por qué los bloques de memoria obtenidos con `OSMemGet` no se devuelven con `OSMemPut`?
3. ¿Qué ventaja tiene separar la lectura/decodificación de imágenes (`TaskPicture`) de su visualización (`ShowPicture`)?
4. Describa el proceso de decodificación BMP dentro de `Read_BMP_ZipFile`: ¿por qué las filas se leen en orden inverso?
